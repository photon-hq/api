`GET /v1/projects/{id}/platforms/resources/{resourceId}`

Reads one resource the project holds. A released number stays readable and reads `retired`, because it remains part of this project's history. A dedicated line given back does NOT: returning it to inventory is what makes it claimable by someone else, so it answers 404 and the operation that returned it is the record that this project once held it. Requires the platforms:read permission bound to the project resource in the path.

<RequestExample>
```typescript TypeScript
import { Photon } from "@photon-ai/api";

const photon = new Photon({
  headers: { Authorization: `Bearer ${process.env.PHOTON_API_TOKEN}` },
});
const result = await photon.projects.platforms.getResource({
  path: {
    id: "id",
    resourceId: "resourceId",
  },
});
```

```python Python
import os

from photon_api import Photon
from photon_api.rpc_generated import GetResourceInput

photon = Photon(headers={"Authorization": f"Bearer {os.environ['PHOTON_API_TOKEN']}"})
result = photon.projects.platforms.get_resource(
    GetResourceInput.model_validate({
        "path": {
            "id": "id",
            "resourceId": "resourceId",
        },
    })
)
```

```rust Rust
use photon_ai_api::{Credential, PhotonClientBuilder, SecretString};

let token = std::env::var("PHOTON_API_TOKEN")?;
let client = PhotonClientBuilder::new()
    .credential("accountServiceKey", Credential::Bearer(SecretString::from(token)))
    .build()?;
let result = client
    .get_resource("id".to_owned(), "resourceId".to_owned())
    .await
    .map_err(|error| format!("{error:?}"))?
    .into_inner();
```
